# Scattered codebooks: recovery tests and exact linear constraints

Contributor and owning account: Chesewip. Agent/session: the owner's continuing Codex Noita investigation. Execution/publication: 2026-09-07. Status: bounded recovery experiments and exact exclusions of a stated family. **No authentic plaintext or key recovered.**

This round tests the gap left by [unknown-map-coordinate-findings.md](unknown-map-coordinate-findings.md): small codebooks can be scattered across all five values in every coordinate. A permutation search can repair sufficiently close generated keys, but fails from blind starts. Separately, exact algebra excludes a specific family of scattered 25-symbol codebooks, even behind an arbitrary output-symbol substitution.

## Inputs and common model

Input is [ciphertext.json](ciphertext.json), SHA-256 `9a24f55e1480b92261ffa3c8f8d0dc7e5f22916e9841b1c3934eaa6c1bd6e529`. Canonical triangular grouping and message order E1, W1, E2, W2, E3, W3, E4, W4, E5 are retained. Raw lengths are 99, 103, 118, 102, 137, 124, 119, 120, 114. No new image transcription, language model or repeated-plaintext equality is used.

An unknown shared injective map assigns observed ciphertext labels to base-5 coordinate triples. The full key is represented as a permutation of 125 coordinate codes, including assignments for unobserved labels. Within each block, decryption flattens those triples, splits the stream into three equal coordinate rows, and zips those rows into input triples. Input symbols have fixed coordinate triples; their names are unknown.

The searches and exact screen below have separately stated block restrictions. Neither inherits every freedom allowed in the preceding report.

## Recovery calibration: a local repair method, not a blind decoder

[scattered_map_search.py](scattered_map_search.py) exchanges assignments of two output labels while retaining a bijection. Half the proposals exchange neighboring cube cells, changing one digit; the others exchange arbitrary cells. It updates only affected decoded positions. Its energy is:

```text
number of occupied input triples - 0.1 * sum(frequency * log(frequency))
```

This encourages fewer occupied triples and concentrates their frequencies. Accepted moves follow a cooling schedule. Every 10,000 proposals, a complete recomputation audits the incremental decoded values, counts and energy. Saved best candidates prioritize support size, then energy. Neither objective authenticates text.

Three independently generated controls use seeds 907413, 907440 and 907441. Each has 27 randomly selected input triples, all five values present in each coordinate, a random permutation of all 125 output labels, period 7 and nine messages of the same lengths as the Eye corpus. All 27 input symbols occur. All 125 output labels are observed in each control; this differs from the eyes' 83 labels.

Warm starts deliberately use the true permutation after a specified number of random key-entry swaps. These are repair tests with privileged information, not unknown-key recovery from scratch. They receive 100,000 proposals, cooling from 0.05 to 0.02.

| Initial random swaps | Control 907413: final support | Control 907440: final support | Control 907441: final support | Exact planted key recovered |
| ---: | ---: | ---: | ---: | --- |
| 0 | 27 | 27 | 27 | 3/3 baselines |
| 5 | 27 | 27 | 27 | 3/3 |
| 10 | 27 | 27 | 27 | 3/3 |
| 20 | 27 | 60 | 27 | 2/3 |
| 40 | 97 | 95 | 96 | 0/3 |

Ten swaps changed 18 or 19 key entries in these cases; twenty changed 31, 34 and 32 respectively. A swap count is not a count of distinct wrong entries. The recovered cases match the original full 125-entry permutation exactly, without requiring a symmetry adjustment.

Each control also receives three blind random starts, 200,000 proposals each, starting temperatures 0.2, 0.8 and 3.0 and ending at 0.02. **All nine blind runs fail to reach the true 27-symbol support**, ending with best supports between 89 and 100. This is evidence of insufficient blind recovery capability, not evidence against scattered fractionation.

The earlier adjacent-only pilot and the initially over-hot mixed-move pilot are retained in `scattered_map_adjacent_calibration.json` and `scattered_map_calibrate.json`. They failed even on the five-swap repair case. The cold repair pilot is retained in `scattered_map_cold_pilot.json`; it recovers the original key. The systematic campaign is in [scattered_map_recovery_controls.json](scattered_map_recovery_controls.json), generated by [scattered_map_recovery_audit.py](scattered_map_recovery_audit.py).

## Exact exclusion of a scattered 25-symbol family

Consider input codebooks whose triples obey:

```text
a*x + b*y + z = d  (modulo 5), with a,b in {1,2,3,4}.
```

The value d is unknown and shared. Each such relation has 25 solutions and uses every digit in every coordinate, so the earlier coordinate-range test does not exclude it. Any subset of one of these 25-point codebooks is also covered. Codebooks with zero coefficients, unions of planes, arbitrary 27-point sets, or nonlinear equations are outside this exact result.

The output-label mapping remains arbitrary and injective. Every retained decoded position provides one linear equation in its contributing unknown output coordinates and the unknown d. Working modulo 5, elimination finds weighted sums of these observed equations that force an impossible output mapping. No key search or guessed text is needed.

The complete screen covers **8,672 configurations**: all 16 nonzero coefficient pairs, each shared period from 2 through the longest retained message, both common body directions, and either retaining or omitting the first raw symbol. The first block is full; only the last may be shorter. Thus this does not cover arbitrary short first blocks or message-specific periods. Periods beyond the longest message add no new partitions. Period 1 cannot map 83 distinct retained output labels into at most 25 input triples under a bijection.

The independent check confirms **8,656 coordinate-collision certificates** and **16 five-point-line certificates**, comprising **26,128 weighted equation identities**. There are two kinds of certificate:

- **Coordinate collision:** weighted sums force all three coordinates of output label 0 to equal those of output label 1. An injective mapping cannot satisfy that.
- **Five-point line:** for the exceptional period-2 cases with a = b squared modulo 5, the equations force labels 0 through 5 to share y and the quantity b*x + z. At most five coordinate triples have those two fixed quantities. Six distinct output labels cannot fit.

The first 512 retained input positions suffice for most certificates; cases that need more use the complete retained corpus. The source equations and all weights are reconstructible. [affine_plane_codebook.json](affine_plane_codebook.json) stores the weights as compressed byte residues to avoid duplicating large arrays. Its explicit encoding is base64 of zlib-compressed, row-major bytes in 0 through 4.

The initial period-2-through-16 screen is retained in [affine_plane_codebook_pilot.json](affine_plane_codebook_pilot.json). It found 472 coordinate-collision certificates and left eight cases unresolved. The five-point-line argument resolves those cases; they were not silently treated as exclusions in the pilot.

Three generated 25-symbol controls, seeds 908100 through 908102, use periods 2, 7 and 13 and coefficient pairs (1,1), (1,2), (3,4). Each has a random unknown output permutation. Their true keys satisfy every equation, and the discovery routine correctly refuses a false coordinate-collision certificate. These are soundness controls with known keys, not blind key-recovery claims.

## Independent checks and reproduction

[verify_scattered_codebooks.py](verify_scattered_codebooks.py) imports no discovery code and uses only the standard library. It independently decrypts and re-encrypts every saved heuristic candidate, checks support and energy, verifies exact control-key repairs, and reconstructs the linear equations by tracing output coordinates to input positions. It then directly adds each certificate's weighted equations modulo 5 and compares the result with the claimed coordinate constraints. It does not repeat Gaussian elimination or infer that heuristic minima are optimal.

It replays **47 heuristic key witnesses**, re-encrypting **48,584 symbols** across the primary campaigns and retained pilots. The verifier also checks that the exact-screen configuration list is complete, that each generated affine control really encrypts its saved plaintext, and that the earlier partial-screen certificates remain valid. Its result is [checked_scattered_codebooks.json](checked_scattered_codebooks.json).

Executed with Python 3.10.0 and NumPy 1.24.3. Only the affine-plane discovery script needs NumPy. From this directory:

```powershell
python scattered_map_recovery_audit.py --phase controls
python scattered_map_recovery_audit.py --phase eyes
python affine_plane_codebook.py --max-period 137
python verify_scattered_codebooks.py
```

The earlier pilot files are retained inputs to the verifier. Discovery runtime fields change on rerun. The primary recovery campaigns took approximately 72 seconds for controls and 61 seconds for eyes in this environment. The complete affine discovery run took approximately 351 seconds. No project build is involved.

## Implication and remaining question

We now have an exact obstruction for these linear 25-point codebooks under the stated shared schedule, and a calibrated picture of one heuristic's limitations on arbitrary scattered alphabets. These are different types of evidence. The true cipher is not identified by either.

The remaining scattered-codebook problem needs stronger relations between complete triples, or a way to obtain a sufficiently accurate initial output map. Nonlinear 25-point relations and arbitrary small codebooks remain open. No global novelty claim is made for permutation search, coordinate fractionation or finite-field elimination.
